Needs Claude Code 2.1.287 or later with mods turned on. Don't install it next to Cache Keeper: both register /cache, /keepwarm and /handoff.

Why

Every message re-reads the whole chat

While the prompt cache is warm, that read is cheap. After a pause longer than the cache window (5 minutes on the API default, 1 hour on a subscription) the next message writes the whole context again at full price. Claude Code caches by itself; it just doesn't tell you when the cache goes cold or what the next message will cost.

$0.20per million tokens, read from a warm cache (Opus 5.5)
$8.00per million tokens, written again after a 1h cache went cold
40×the difference, for the same context, after every long pause

What it does

Three jobs

See what's happening

  • The band above the prompt: cache state, context size, what a rewrite costs now, session and today's cost, plan limits.
  • /cache: the full status and every setting.
  • TTL detection: measures whether you run on the 5-minute or 1-hour cache.
  • Cache-break alert: names the cause when a warm cache is rewritten (model switch, changed CLAUDE.md, MCP tools, settings).

Avoid cold restarts

  • Cooling warning shortly before a big cache goes cold.
  • /keepwarm: small pings keep the cache alive, and it warns past the point where a rewrite is cheaper.
  • Cold-send guard: before you send into a big cold context, it asks: send, compact first, or cancel.

Keep the context small

  • /handoff: Claude writes a summary, saves it, clears the chat and carries on in a fresh one.
  • Handoff vs keep-warmnew: /keepwarm says when a handoff is cheaper, and what every later turn saves.
  • 140k remindernew: past 140k tokens it suggests a handoff and asks again every 100k.

How to use it

A typical session

  1. Work as usual.

    The band shows the cache warm, cooling or cold and what a rewrite would cost right now.

  2. Before a short break, type /keepwarm.

    30 minutes by default on the 5-minute cache, 4 hours on the 1-hour cache. If a handoff would be cheaper, it says so with both prices.

  3. Before a long break, or when you're done, type /handoff while the cache is warm.

    On a cold cache the handoff would have to rewrite everything too. When the summary is in, press c on the band or type /handoff continue to clear and carry on.

  4. When the chat grows past 140k, decide.

    Token Keeper shows a notice and asks:

    ℹ️ This chat is at 140k tokens: every turn re-reads all of it ($0.03), and a long context gets less reliable. A /handoff or /compact (about $0.19, either) carries on with about 23k: about $0.02 less per turn.

    ❯ Handoff now · Remind me after another 100k (240k) · No more reminders

How the numbers work

Where the figures come from

A ping

One cache read of the whole context, sent every 3.5 minutes on the 5-minute cache and every 52 minutes on the 1-hour cache. It never lands in your chat.

The break-even

A rewrite costs as much as (write price ÷ read price) pings, whatever the context size. On Opus 5.5 with the 5-minute cache that is about 1h 28m of pinging.

A handoff

One read of the context, the handoff text (the average of your last five), and the fresh chat's start, measured from /context. Files the fresh chat reads again are not counted.

Everything stays on your machine, under ~/.claude/mods-data/token-keeper/. The only extra requests are the keep-warm pings, and only while /keepwarm is on.

Based on Cache Keeper by Nate Herk (MIT). Prices are API list prices; on a subscription they stand for plan-limit use.
